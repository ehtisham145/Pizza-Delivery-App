Step 1 — Model banao
models.py mein Notification table banao jisme id, user_id, title, message, is_read, created_at ho.

Step 2 — Pydantic Schemas banao
schemas.py mein sirf 3 schemas chahiye:

NotificationOut — response ke liye
NotificationListOut — pagination ke liye
UnreadCountOut — badge count ke liye


Step 3 — Helper Function banao
services.py ya utils.py mein ek function banao:
create_notification(db, user_id, title, message)
Yeh function tab call karo jab order status change ho.

Step 4 — Order Service mein call karo
Jab bhi order ka status update ho — confirmed, preparing, out_for_delivery, delivered, cancelled — wahan create_notification() ko call karo aur message pass karo.

Step 5 — Router banao
routers/notifications.py mein 4 endpoints banao:

GET /notifications — list with pagination
PATCH /notifications/{id}/read — ek mark as read
PATCH /notifications/read-all — sab mark as read
GET /notifications/unread-count — badge ke liye count


Step 6 — Authentication lagao
Har endpoint par get_current_user dependency lagao taake sirf logged-in user apni notifications dekh sake.

⚙️ The Stats Endpoint — What to Return
GET /api/v1/admin/stats

Response:
{
  "total_orders_today": 24,
  "revenue_today": 18450.00,
  "pending_orders": 5,
  "total_users": 312,
  "total_orders_all_time": 1894,
  "total_revenue_all_time": 945000.00

This is a single endpoint but does multiple DB aggregation queries behind the scenes using SQLAlchemy's func.count() and func.sum().

⚙️ Business Logic Rules
•	Admin cannot deactivate another admin — protect against this
•	Admin cannot change their own role — prevents accidental self-lockout
•	The orders list for admin should support filtering by status — ?status=pending
•	Deactivating a user should not cancel their active orders — handle separately
•	Keep all admin routes under /api/v1/admin/ prefix and protect with require_admin dependency
