🗄️ Database Model
Column	Type	Notes
id	UUID	
order_id	FK → Order	one-to-one
method	Enum	cash_on_delivery, card
status	Enum	pending, paid, failed, refunded
amount	Float	copied from order total
paid_at	DateTime	null until payment confirmed
created_at	DateTime	





📡 API Endpoints
Method	URL	Who	What
GET	/api/v1/payments/my-payments	Customer	My payment history
GET	/api/v1/payments/{order_id}	Customer	Payment for a specific order
PATCH	/api/v1/payments/{id}/status	Admin	Update payment status
GET	/api/v1/payments	Admin	All payments list
⚙️ Business Logic Rules
•	Payment record is auto-created when order is placed — customer never manually creates it
•	For cash_on_delivery — status starts as pending, admin marks paid after delivery
•	For card — in a real app this would call Stripe, but for your project just expose an endpoint for admin to manually mark it
•	When order is cancelled — payment status should update to refunded if it was paid
•	amount must match order.total_price exactly — validate this
•	One order = one payment record, always — enforce unique constraint on order_id
